# 改写手法详解与对照表

本文件是 `humanize-rewrite` 技能的详细参考。每次执行改写任务前必须完整阅读一遍。

## 1. 核心改写手法

### 1.1 短句拉长（最重要）

把短促、压缩的表达拆开说完整，补出被省略的成分（主语、时间状语、程度说明）。

| 原文短句 | 改写后 |
|---------|--------|
| 现在可以了 | 到了现在这个时候，已经可以实现这一点了 |
| 它能用 | 它已经变成了一个能够真正打开并进行使用的工具 |
| 成本低 | 在使用成本这一方面确实被压低到了一个比较友好的程度 |
| 上线了 | 已经正式进入到了上线可用的状态 |
| 效果不错 | 从实际运行出来的效果这个角度来看，确实处在一个还不错的水平 |
| 免费用 | 可以在不花费任何费用的情况下直接进行使用 |
| 三分钟搞定 | 大概只需要三分钟左右的时间就能够全部完成 |
| 不难 | 整体上手难度其实处在一个比较低的程度 |
| 大家都在用 | 目前这一工具已经被比较多的使用者接纳并且投入到日常使用当中了 |
| 值得一试 | 是一个值得抽出时间来进行一次尝试的选择 |

### 1.2 连接词与缓冲词

高频使用以下词汇，让句子产生人工扩写的"慢"感：

- 指示类：这一个、这个事情、这一类、这一些、这个环节、这个方面
- 时间/阶段类：在这个时候、在目前这个阶段、在……之后、从……以来
- 范围类：在……里面、在……当中、对于……来说
- 程度类：比较、更加、确实、其实、相对、一定程度上
- 动作类：进行、能够、实现
- 结构类：从这个角度来看、在本质上、具体来说、换句话说、也就是说
- 名词化后缀：方面、状态、程度、环节、流程、情况、水平、层面

### 1.3 口语/网感词 → 解释型表达

| 口语/网感表达 | 改写为 |
|--------------|--------|
| AI | 人工智能（按语境，若为专有名词组成部分则保留，如"AI Coding"） |
| 用 | 进行使用 |
| 做 | 制作出来 / 完成 |
| 改 | 进行调整 |
| 试 | 进行尝试 |
| 跑（模型） | 运行 |
| 翻车 | 出现问题 / 出现差错 |
| 顺手 | 使用起来比较顺手 |
| 白花钱 | 白白花费了一笔成本 |
| 薅羊毛 | 以比较低的成本获取到权益 |
| 卷 | 竞争激烈 |
| 踩坑 | 遇到问题 / 走了一些弯路 |
| 上手 | 完成上手 / 进入能够使用的状态 |
| 一波 | 一轮 / 一批 |
| 拉满 | 提升到了一个很高的程度 |
| 直接 | 直接进行 / 干脆 |
| 搞定 | 完成 / 处理完毕 |
| 种草 | 产生兴趣 / 被推荐 |
| 打工人 | 普通上班族（按语境） |
| 硬核 | 门槛比较高 / 比较专业（按语境） |

### 1.4 术语解释化（不改变原意）

| 原文术语 | 可改为 |
|---------|--------|
| Skill 化 Agent | 具有特定技能的智能代理 |
| 节点式画布 | 节点式的画布界面 |
| 工作流 | 工作流程 |
| Prompt | 提示词（原文刻意强调英文术语时保留 Prompt） |
| Token | Token（专有名词，保留；可补充解释"也就是模型进行计算时的计费单位"之类，前提是不改变原意且为常识性解释） |

**注意**：解释化必须保守。只有当解释是行业公认常识、且完全不改变原意时才允许补充，否则一律保留原词。品牌名、模型名、公司名（如 DeepSeek、Codex、LibTV、MiniMax H3、WeaveFox、Flova AI）一个字母都不能改。

## 2. 改写前后完整段落示例

### 原文

> 现在可以了。最近 WeaveFox 更新了一个新功能，能把设计稿直接转成代码，成本低，上手也快，试了一下基本没翻车。这对前端来说，确实省了不少事。

### 改写后

> 到了现在这个时候，已经可以实现这一点了。在最近这一段时间里面，WeaveFox 进行了一次功能层面的更新，推出了一项新的能力，能够把设计稿直接转换成为可以使用的代码。在使用成本这一方面确实被压低到了一个比较友好的程度，同时在上手这个环节也处在一个比较快的水平。我自己进行了一次尝试，从运行的结果来看，基本上没有出现什么问题。对于前端开发者这个群体来说，这一类工具确实替他们省下了不少的工作量。

## 3. 输出红线（禁止事项）

1. 禁止压缩、总结、概括式改写——那是最典型的 AI 味来源。
2. 禁止漏句。原文每一句都必须被处理到。
3. 禁止新增原文没有的事实、数据、案例、观点。解释性成分允许，但必须是常识且不改原意。
4. 禁止调整段落顺序、合并段落、删除小标题。
5. 禁止改动：品牌名、模型名、英文名、价格、时间、数字、话题标签（#xxx）、链接、报名方式。
6. 禁止输出改写说明、提纲、开场白（如"以下是改写后的文章"）。
7. 禁止因为追求自然流畅而放弃扩写痕迹——本技能的目标恰恰是保留一定机械扩写感。

## 4. 自检流程（输出前逐项核对）

1. **数字与专有名词比对**：把原文中所有数字、价格、时间、品牌名、模型名、英文术语列出来，逐个与改写稿比对，必须完全一致。
2. **段落顺序比对**：改写稿的段落数量与顺序必须与原文一一对应。
3. **完整度检查**：确认原文每句话的内容点都出现在改写稿中，没有跳过、没有合并删减。
4. **关键内容检查**：小标题、结尾总结、行动引导、官网链接、报名方式、话题标签全部保留。
5. **字数检查**：改写稿字数 ÷ 原文字数，结果应在 1.3 ～ 1.8 之间。低于 1.3 说明压缩了，回去重写扩写不足的段落。
6. **语言质量检查**：无错别字、无病句、无英文乱入、无指代不清（"这一个""这个事情"不能多到让读者迷失主语）。
7. **风格检查**：通读一遍，确认有明显的句子拉长感、解释感和轻微翻译腔。如果读起来过于利落精炼，说明改写强度不够，需要回炉。
